[chat] Never set fixed pixel `width`/`height` directly on `<img>` elements in sections/blocks. The theme's `assets/base.css` (line 48) applies a global `img { width: 100%; height: auto }` baseline that works with `srcset` and merchant uploads of any aspect ratio. Fixed `<img>` sizing fights this baseline and breaks when logos/photos aren't the exact dimensions in Figma. Instead, size the WRAPPER (`.section__image { width: 148px; height: 74px }`) and let the `<img>` fill it with `max-width: 100%; max-height: 100%; width: auto; height: auto; object-fit: contain`. This is the pattern used by `.background-image-container img`, `.card-gallery > img`, `.product-media-container img` in base.css.
[chat] When Figma shows an image at fixed pixel dimensions (e.g. 148x74 logo), translate those dimensions onto the WRAPPER div, never the `<img>` itself. The image element should always stay fluid via `max-width: 100%` + `object-fit`.
[chat] There is a GLOBAL CSS rule `.shopify-section:not(.header-section) :is(.section,.cart-summary) { background: transparent }` (in `assets/base.css` or similar) that forces transparent backgrounds on any `.section` element inside non-header shopify-sections. This SILENTLY OVERRIDES color_scheme backgrounds on new sections — so a section using `color-{{ section.settings.color_scheme }}` will render with no background even though the scheme defines one. When building any new section that needs a visible background from its color_scheme, either (a) apply the color scheme class to a different root element (not `.section`), (b) add a scoped override in the section's `{% stylesheet %}` like `.shopify-section .my-section.section { background: var(--color-background) }`, or (c) wrap content in a div with the color-scheme class instead of relying on `.section`. Always test new sections with non-default color schemes to catch this.
